## Regla de ejecución

Cada landing debe tener un brief individual en `briefs/{slug}.md` y completar la misión de
posicionamiento antes de editar el copy. El breve semanal es:

| Momento | Entregable |
| ------- | ---------- |
| Inicio de semana | Validar brief, keyword principal y consultas de Search Console disponibles; no inventar volúmenes ni posiciones |
| Mitad de semana | Contrastar cada afirmación del producto contra la ficha de módulo y verificar capturas/datos |
| Cierre de semana | Copy y metadatos revisados, enlaces contextuales recíprocos cuando ambas páginas existen, tests/build y registro para MKT-109 |

Las tareas con fecha concreta representan días de trabajo dentro de las ventanas siguientes; el
orden se puede mover dentro de cada semana, pero no se inicia una página sin brief revisado.

## Criterios para cerrar cada entrega

- [ ] Brief completo con misión, keyword única, intención y keywords excluidas.
- [ ] Fuentes factuales anotadas; no hay promesas fuera del producto actual.
- [ ] Media autoalojada, optimizada, con `alt` y sin PII/datos reales.
- [ ] Meta title, description, FAQ y enlazado revisados para evitar duplicación.
- [ ] Tests focalizados y `npm run build` en verde.
- [ ] Landing incluida en sitemap; despliegue productivo confirmado por separado.
- [ ] Piezas distribuidas registradas en MKT-109 con canal, fecha y destino.
