## Resumen

Terrenario gana una presencia pública indexable y medible: una home y diez landings estáticas,
metadatos SEO por URL, preguntas frecuentes y datos estructurados, recursos de rastreo y
trazabilidad agregada desde la visita hasta el login completado.

La salida incluye además el resumen operativo por correo y la redirección canónica de los dominios
alternativos hacia `app.terrenario.com`.

Esta es una **release parcial** de la épica `MKT-100`. La épica no se cierra: `MKT-107`–`MKT-110` y
`MKT-199` continúan pendientes. La publicación se autoriza como corte independiente para poner en
producción la base técnica y empezar a obtener evidencia real de indexación y conversión.

---

## Lo que verá quien visite Terrenario

### Diez páginas públicas que explican el producto

Se publican siete landings de funcionalidades y tres por perfil de uso, con contenido HTML
pre-renderizado que no depende de ejecutar JavaScript para poder indexarse. La home actúa como hub y
cada landing enlaza el acceso y las capacidades relacionadas.

La landing de control de cosechas se especializa en **olivar**: explica kilos por terreno, destinos,
rendimiento de aceite en litros por cada 100 kg de aceituna, kilos por árbol e histórico entre
campañas. El recorrido desarrolla problema, capacidades, beneficios verificables, FAQ y CTA sin
prometer precio, plataformas o resultados que el producto no pueda sostener.

### SEO técnico por URL

Cada página publica un `title`, descripción, canonical, `hreflang="es-ES"` y un único `h1`. Open
Graph y Twitter son configurables por landing. El JSON-LD contiene `Organization`,
`SoftwareApplication` y el `FAQPage` que corresponde exactamente a las preguntas visibles.

`robots.txt` permite las páginas públicas, excluye la aplicación autenticada y anuncia un
`sitemap.xml` con las once URLs indexables.

### Medición sin analítica de terceros

La API cuenta visitas a landings y enlaza de forma agregada la entrada a login y el login exitoso.
`GET /api/v1/ops/signals` incorpora la conversión por landing de los últimos siete días y el resumen
semanal muestra las páginas con mejor conversión. No se instala Google Analytics ni se conserva el
referer en crudo por persona.

### Resumen operativo por correo

El destinatario de alertas recibe un resumen diario y otro semanal con sesiones, embudo de login,
conversión y alertas activas. El resumen semanal incorpora también el rendimiento de las landings.

## Cambios de plataforma

Los dominios `terrenario.com`, `www.terrenario.com`, `terrenario.es` y `www.terrenario.es` pueden
redirigir con `301` al host canónico `app.terrenario.com`, conservando ruta y query string. La
funcionalidad permanece inactiva si no se configuran sus variables.

---

## Configuración de despliegue

Antes de crear el tag hay que comprobar en producción:

| Ajuste / acción | Valor o comprobación |
|---|---|
| `Ops__AlertEmail` | Destinatario válido; también recibe los resúmenes operativos |
| `Ops__SummaryEnabled` | `true` para activar los resúmenes diario y semanal |
| `Domains__CanonicalHost` | `app.terrenario.com` |
| `Domains__AlternateHosts` | `terrenario.com`, `www.terrenario.com`, `terrenario.es`, `www.terrenario.es` |
| DNS y certificados | Ejecutar el runbook y `infra/azure/enlazar-dominios.sh` tras crear los registros DNS |
| Webmaster | El alta y baseline pertenecen a `MKT-107`; no bloquean este corte parcial |

No hay migraciones de base de datos ni dependencias nuevas de producción.

## Secuencia de publicación

1. Fusionar estas notas en `develop`.
2. Revisar y fusionar el PR `develop` → `main` mediante **merge commit**, no squash.
3. Verificar SLO, configuración y smoke indicados arriba.
4. Crear el tag anotado sobre el merge commit de `main`:

   ```bash
   git tag -a v0.9.0 -m "Release v0.9.0 — Base pública de crecimiento orgánico"
   git push origin v0.9.0
   ```

5. Aprobar el entorno `produccion` y verificar el despliegue.
6. Actualizar estas notas a `publicado` con la evidencia post-despliegue.
