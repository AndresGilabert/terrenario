# Release v0.9.1 — Las rutas públicas sirven las landings pre-renderizadas

> **Fecha prevista**: 2026-09-21
> **Tipo**: patch — corrección de publicación, sin funcionalidad nueva
> **Tag previsto**: `v0.9.1` · sobre [v0.9.0](./v0.9.0.md)

---

## Resumen

Corrige la publicación de las landings introducidas en `v0.9.0`. Los HTML pre-renderizados estaban
en `wwwroot`, pero las rutas públicas normales devolvían el `index.html` vacío de la SPA. La ruta
directa al fichero (`/funcionalidades/control-cosechas/index.html`) sí mostraba la landing, señal de
que el problema estaba en el pipeline HTTP y no en el build ni en el despliegue.

## Causa

`PrettyUrlIndexMiddleware` existía y tenía pruebas unitarias, pero no se registró en `Program.cs`.
El test de la variante con barra final asumía además que `UseDefaultFiles` la resolvería; App Service
falsó esa hipótesis en producción.

## Corrección

- Se registra `PrettyUrlIndexMiddleware` antes de `UseDefaultFiles`, `UseStaticFiles` y el fallback.
- Sirve el `index.html` físico tanto para `/funcionalidades/{slug}` como para la variante con barra.
- La raíz sigue gobernada por `home.html` y las rutas API siguen excluidas.
- El smoke de producción comprueba una landing canónica real: `h1`, contenido de olivar, canonical y
  JSON-LD. Un fallback SPA ya no puede dar un despliegue verde.

## Breaking changes

Ninguno. No hay migraciones ni cambios de configuración.
